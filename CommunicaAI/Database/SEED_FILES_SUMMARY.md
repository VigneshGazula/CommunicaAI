# Database Seed Files - Summary

## Overview

This document summarizes the PostgreSQL seed files created for the CommunicaAI project. These files were generated by analyzing the existing C# code and extracting the exact table names, column names, and seed data used in the application.

## Files Created

### 1. `Seeds/00_master_seed.sql`
**Purpose**: Master orchestration script that runs all seed files in order

**Features**:
- Enables required PostgreSQL extensions (`uuid-ossp`, `pgcrypto`)
- Executes all individual seed scripts
- Displays summary statistics after seeding
- Provides verification queries

**Usage**:
```bash
psql -h localhost -U postgres -d communicaai -f 00_master_seed.sql
```

- **3 Categories**: Technical, Behavioral, HR
- **3 Difficulty Levels**: Easy, Medium, Hard

**Total Questions**: 155 questions

**Table Structure**:
```sql
"QuestionBanks" (
    "Id" uuid PRIMARY KEY,
    "Role" varchar(100),
    "Category" varchar(50),
    "Difficulty" varchar(50),
    "QuestionText" varchar(1000),
    "CreatedAt" timestamp
)
```

**Key Features**:
- Uses `gen_random_uuid()` for PostgreSQL-native UUID generation
- Uses `NOW()` for timestamps
- Properly escapes apostrophes in question text (e.g., `you''re` → `you're`)
- Matches exact column names from EF Core migrations

**Usage**:
```bash
psql -h localhost -U postgres -d communicaai -f 01_seed_question_bank.sql
```

3. **`Services/QuestionBankService.cs`**: Extracted exact seed data (lines 93-319)

## Key Differences from C# Code

### Table Names
- **EF Core Convention**: Uses DbSet property name (e.g., `QuestionBanks`)
- **PostgreSQL**: Quoted identifiers preserve case (e.g., `"QuestionBanks"`)

### UUID Generation
- **C# Code**: `Guid.NewGuid()`
- **PostgreSQL**: `gen_random_uuid()`

### Timestamps
- **C# Code**: `DateTime.UtcNow`
- **PostgreSQL**: `NOW()`

### String Escaping
- **C# Code**: Uses verbatim strings or escapes
- **PostgreSQL**: Doubles single quotes (`''`)

## Alternative Seeding Method

Instead of SQL scripts, you can use the built-in API endpoint:

```bash
# Development
POST http://localhost:5000/api/question-bank/seed

# Production
POST http://your-domain.com/api/question-bank/seed
```

**Limitations**:
- Only works if `QuestionBanks` table is empty
- Requires application to be running
- Uses same seed data as SQL scripts

**Advantages of SQL Scripts**:
- Can be run before application starts
- Works during initial deployment
- Can be automated in CI/CD pipelines
- Doesn't require application dependencies
- Faster for large datasets

## Integration with EF Core Migrations

The seed scripts are designed to work alongside EF Core migrations:

1. **Create Database**: `dotnet ef database update` (creates schema)
2. **Seed Data**: `psql -f 00_master_seed.sql` (inserts data)
3. **Verify**: Run verification queries

**Important**: Always run migrations before seed scripts to ensure tables exist.

## AWS Deployment Workflow

For AWS EC2 deployment:

```bash
# 1. SSH into EC2 instance
ssh -i your-key.pem ubuntu@your-ec2-ip

# 2. Navigate to application directory
cd /var/www/communicaai

# 3. Apply migrations
dotnet ef database update --connection "Host=localhost;Database=communicaai;Username=postgres;Password=your_password"

# 4. Run seed script
sudo -u postgres psql -d communicaai -f Database/Seeds/00_master_seed.sql

# 5. Verify seeding
sudo -u postgres psql -d communicaai -c "SELECT COUNT(*) FROM \"QuestionBanks\";"
```

## Maintenance

### Adding New Questions

**Option 1**: Update SQL script
1. Edit `01_seed_question_bank.sql`
2. Add new INSERT statements
3. Re-run script (after truncating table if needed)

**Option 2**: Use API
```bash
POST http://localhost:5000/api/question-bank
Content-Type: application/json

{
  "role": "Software Engineer",
  "category": "Technical",
  "difficulty": "Medium",
  "questionText": "Explain microservices architecture."
}
```

### Adding New Roles

1. Add questions for the new role in `01_seed_question_bank.sql`
2. The role will automatically appear in the metadata API response
3. No code changes needed (roles are dynamically retrieved from database)

### Adding New Categories or Difficulties

Same process as adding new roles - just insert questions with new category/difficulty values.
